1. Executive Abstract & Objectives

In healthcare systems, inventory stockouts of critical therapeutics, dispensing expired medications, and disconnected prescription workflows present life-threatening hazards and substantial financial leakage. The Pharmacy Inventory and Prescription Tracking System implements a centralized relational database architecture addressing the complete pharmaceutical lifecycle: doctor consultation, prescription issuance, branch-level inventory holding, automated replenishment triggers, and supply-chain procurement.

DA1 Source of Truth Fidelity: The student's approved DA1 submission (ER, EER, Relational Mapping, and Normalization up to BCNF) is strictly treated as the inviolable architectural source of truth. Every entity, attribute, cardinality, and functional dependency documented in DA1 has been faithfully implemented.

5. DA1 Normalization Analysis (Pages 7 to 15)

In Pages 7 through 15 of DA1, each table was analyzed using sample rows (P01–P05, D01–D05, M01–M05) and functional dependencies:

1. Decomposed Tables (Resolving Normalization Violations)

Table 1: PHARMACY (DA1 Page 7 & 8) — Resolving Transitive Dependency 1NF • 2NF • Decomposed to 3NF/BCNF

Initial FDs: { Pharmacy_ID → Rating, Name, City, Street, Contact_No }, { City → State }
Violation: Clearly Pharmacy_ID → City and City → State creates a Transitive Dependency. Hence not in 3NF.
Decomposition:
• R1 (Pharmacy): (Pharmacy_ID, Rating, Name, City, Street, Contact_No) with FD: Pharmacy_ID → Rating, Name, City, Street, Contact_No
• R2 (City_State): (City, State) with FD: City → State
Result: Both R1 and R2 satisfy 1NF, 2NF, 3NF, and BCNF.

Table 4: DOCTOR (DA1 Page 9 & 10) — Resolving BCNF Violation Decomposed to BCNF

Initial FDs: { (Doctor_ID, Hospital_ID) → Experience, Contact_No, First_Name, Last_Name, Qualification }, { Qualification → Hospital_ID }
Violation: Qualification → Hospital_ID violates BCNF because Qualification is not a superkey.
Decomposition:
• R1: (Doctor_ID, Hospital_ID, Experience, Contact_No, First_Name, Last_Name)
• R2: (Qualification, Hospital_ID)
Result: Decomposed relations satisfy BCNF.

Table 8: BILL (DA1 Page 11) — Resolving Partial Dependency Decomposed to 2NF/3NF/BCNF

Candidate Key: (Bill_ID, Pharmacy_ID, Patient_ID)
FDs: { Bill_ID → Patient_ID }, { Patient_ID → Amount } ∴ { Bill_ID, Patient_ID → Amount }
Violation: Patient_ID → Amount is not in 2NF because a proper subset of candidate key determines non-key attribute Amount.
Decomposition:
• R1: (Bill_ID, Pharmacy_ID, Patient_ID)
• R2: (Patient_ID, Amount)
Result: Decomposed relations are in BCNF.

Table 9: HOSPITAL (DA1 Page 12) — Resolving 2NF Partial Dependency Decomposed to 2NF/3NF/BCNF

Candidate Key: (Hospital_ID, Pharmacy_ID)
FD: (Hospital_ID, Pharmacy_ID) → City, State, Street, Name, Contact, but Hospital_ID → City, State, Street, Name, Contact.
Violation: Violates 2NF (partial dependency on Hospital_ID).
Decomposition:
• R1: (Hospital_ID, City, State, Street, Name, Contact)
• R2: (Hospital_ID, Pharmacy_ID)
Result: Decomposed relations satisfy BCNF.

6. Stored Programs & Exception Handling

The system operationalizes procedural database logic in MySQL 8.x using 6 Stored Procedures, 5 Functions, and 5 Triggers with SIGNAL SQLSTATE '45000':

1. Stored Procedures (CALL execution)

  • add_patient(p_id, fname, lname, dob, sex, street, city, state, contact): Validates DOB ≤ CURDATE(), sex in ('M','F','O'), and inserts into PATIENT and PATIENT_CONTACT atomically.
  • add_medicine(p_id, name, manu, exp, price, pharm_id, stock, reorder): Enforces Price > 0 and Exp > Manu; inserts formulary record and initializes INVENTORY.
  • restock_medicine(pharm_id, med_id, qty, ref_id): Atomically increments branch stock and writes audit log to STOCK_LOG.
  • create_prescription(presc_id, doc_id, pat_id, date): Cross-validates practitioner and patient registration before creating prescription header.
  • generate_bill(bill_id, pharm_id, pat_id, presc_id): Computes exact total from prescription items, checks stock availability, decrements inventory, and records the bill.
  • place_order(order_id, supp_id, pharm_id, qty, date, arrival, pay, status): Registers procurement purchase order.

2. Database Triggers

Trigger Name Event & Timing Enforced Business Rule / Exception Handling
trg_before_inventory_update BEFORE UPDATE on INVENTORY Throws SIGNAL SQLSTATE '45000' if quantity drops below zero (prevents negative stock). Refreshes timestamp.
trg_after_inventory_update AFTER UPDATE on INVENTORY Computes delta (NEW.Qty - OLD.Qty) and automatically inserts an audit row into STOCK_LOG without manual intervention.
trg_validate_bill_amount BEFORE INSERT on BILL Throws SIGNAL SQLSTATE '45000' if invoiced bill amount is negative.
trg_before_order_insert BEFORE INSERT on ORDER Validates that arrival date is not earlier than placement date.
trg_validate_medicine_insert BEFORE INSERT on MEDICINE Redundant safety guard enforcing chronological expiration and positive pricing.

3. Deterministic Functions

get_medicine_price(med_id), get_patient_prescription_count(pat_id), calculate_prescription_total(presc_id), get_pharmacy_revenue(pharm_id), and get_medicine_stock(pharm_id, med_id) return scalar values for immediate reporting.
